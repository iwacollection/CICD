# Reproducible AArch64 cross-build fixture

This fixture builds a Linux AArch64 executable on an x86_64 Linux host. It separates the Conan build profile (where build tools run) from the Conan host profile (where the produced library and executable run).

## Candidate status and target contract

Debian Forky is Debian testing, not a released stable distribution. The image pins Forky for the base OS, GCC and target sysroot; it imports only the statically linked `qemu-user` package from the same dated Sid archive snapshot because Debian's tracker still lists three open QEMU CVEs against Forky's current 11.1.2 package. The rest of the system retains Forky release priority. This image is an isolated build-toolchain candidate only and is not a production runtime base. It is being evaluated because the earlier Trixie image scan surfaced vulnerable versions of QEMU, libxml2, util-linux, Python and cross sysroot components. Newer package versions do not themselves prove security: the normal HIGH/CRITICAL Trivy gate, SBOM, provenance, ABI and runtime checks must all pass without suppressions or policy exceptions before promotion.

- Target triple: `aarch64-linux-gnu`
- Build-host compiler: native x86_64 GCC/G++ 13.5.0 (`gcc-13`, `g++-13`)
- Target compiler: AArch64 GCC/G++ 13.5.0 (`gcc-13-aarch64-linux-gnu`, `g++-13-aarch64-linux-gnu`)
- Target ABI: Linux AArch64, `armv8`, `libstdc++11`, C++17
- Sysroot root: `/usr/aarch64-linux-gnu` (cross glibc 2.43-3cross8; Linux UAPI headers 7.2.12-1)
- Base image: pinned official Debian Forky slim (testing) amd64 manifest digest `sha256:27b88700aef98dd3dd0b32538f8e5d662a88237ec8fbf969254c8d3c93dfdab1`
- APT snapshot: `20261108T000000Z`
- APT: 3.3.6 (CVE-2026-109518 fixed); cross binutils: 2.47.50.20261021-1; QEMU user-mode: 1:11.1.3+ds-1 (static binary from Debian Sid snapshot `20261108T000000Z`; QEMU package provenance is included in the SDK digest)
- Conan CLI: 2.34.0, installed from the upstream Linux AMD64 release `.deb` after verifying SHA-256 `94d34280e3915535bd73ac9e6896b11a5d0dea31b6c04f8c1c1acf9bf61013a1`
- Third-party dependency: `fmt/11.0.2`
- Runtime validation: `qemu-aarch64 -L /usr/aarch64-linux-gnu`

### Package source boundary

| Component | Archive suite | Immutable snapshot | Pinned identity |
|---|---|---|---|
| Base OS, APT, native/cross GCC, cross glibc, Linux headers, Binutils, CMake/Ninja | Debian Forky | `20261108T000000Z` | Exact package versions are asserted during image build and again by `ci/verify.sh` |
| QEMU user-mode emulator only | Debian Sid | `20261108T000000Z` | `qemu-user=1:11.1.3+ds-1`, static user-mode binaries |

The Sid repository is added only to obtain the QEMU release that fixes the three issues still open against Forky's `1:11.1.2+ds-3`. The system upgrade and all compiler/sysroot package selection explicitly target Forky; QEMU is installed separately by exact version. No Sid upgrade is applied to the base system. The verifier records the QEMU package version and source snapshot in `target-sdk.lock` and incorporates both into the SDK cache digest. This mixed-suite edge is intentional, isolated and subject to the same Trivy gate as every other package.

The Candidate image is built on an amd64 runner and contains the cross compiler, target headers/libraries and QEMU user-mode emulator. This is not an ARM runner and does not prove device-specific behavior. Forky remains unpromoted until the security gate passes.

## Host versus target

- `profiles/build` is x86_64 and explicitly selects native `/usr/bin/gcc-13` and `/usr/bin/g++-13`. Conan build-context tools and build requirements run here.
- `profiles/host` is armv8. Conan host-context packages, fmt and application outputs are built for AArch64.
- `tools.build:compiler_executables` in the host profile selects the AArch64 GCC frontends; the separate build profile selects the native x86_64 GCC 13 binaries.
- Both Ninja and GNU Make are installed: the top-level fixture uses Ninja, while some Conan package recipes configure source builds with the `Unix Makefiles` generator.
- `ci/aarch64-toolchain.cmake` configures CMake's Linux/AArch64 target and restricts system include/library lookup to the target triplet root.

## Identity and cache contract

The checked-in `ci/target-sdk.lock` is marked bootstrap-required; it is not represented as a verified lock. Candidate bootstrap must replace it with the exact identity generated by this pinned image. Commit that output before switching CI from bootstrap to strict lock verification. The separately reviewed Conan dependency lock remains pinned to the existing fmt recipe revision.

The SDK identity records target triple, cross compiler and native build-host compiler package revisions, linker identity, sysroot file-tree SHA-256 (including symlink targets), Linux UAPI header revision, APT snapshot, package inventory digest, combined SDK digest and emulator identity.

Strict verification refuses a missing or changed `target-sdk.lock`. The Conan `conan.lock`, both profiles, CMake toolchain file and actual target SDK lock are required cache-fingerprint inputs. A different ABI, sysroot, SDK or dependency lock cannot be treated as the same target cache.

## Target cache isolation

`ci/cache-key-files.json` is the fixture's cache-fingerprint contract. The verifier requires every listed input to exist and hashes the relative path and content for the Conan recipe and lockfile, host and build profiles, CMake AArch64 toolchain definition, target SDK/sysroot identity lock, CMake project and public headers/source files.

The computed fingerprint is recorded in `.ci-telemetry/cache-fingerprint.txt` and copied into `build/arm64/build-evidence.json`. A missing input fails the build rather than falling back to a partial key.

The disposable Conan package cache and ccache are separate directories. Their namespace contains the AArch64 target triple, exact GCC version, standard-library ABI, C++ standard and target SDK digest. A change in sysroot/compiler/ABI gets a different namespace. Ccache also performs compiler/input hashing; the namespace is an additional isolation boundary.

This fixture proves target-aware fingerprint calculation and local cache-directory isolation. It does not claim that GitHub Actions persistent cache restore/save is wired into the production DAG; that integration requires an Active immutable toolchain and corresponding target project node.

## Verification

The verifier consumes the committed Conan dependency lock and, after bootstrap, the committed SDK identity lock. It performs Conan graph resolution/install, CMake/Ninja configure and compile/link, ELF machine/dependency and ARM attributes inspection, GLIBC/GLIBCXX/CXXABI symbol-version compatibility against the target sysroot, no-RPATH/RUNPATH validation, CTest using QEMU and a direct QEMU run. It writes evidence with timings, cache identity and artifact SHA-256.

QEMU testing is a Linux userspace smoke test only. Kernel/driver compatibility, hardware performance, bootloader integration and board-specific behavior still require a real ARM64 device runner/HIL setup.
