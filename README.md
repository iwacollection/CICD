# 企业 CI/CD 平台

这是一个面向企业多项目的软件构建与交付平台。

它把分散在不同代码仓库中的应用和嵌入式固件，放进一套统一、可追溯、可验证的交付流程中：从代码提交开始，完成构建、测试、制品保存、安全检查、环境发布，并在发布失败时支持回退到已验证版本。

## 平台做什么

- **统一构建**：管理不同项目的构建任务、项目依赖和 JDK、编译器、厂商 SDK 等工具链。
- **安排构建顺序**：识别项目之间的依赖，先构建被依赖的组件，再构建上层项目。
- **管理构建结果**：为软件包和固件记录来源、构建环境、依赖关系及校验值。
- **检查交付风险**：执行测试、安全检查，并保留软件成分、来源和签名等证据。
- **控制发布过程**：让经过验证的同一份制品进入不同环境，支持灰度、蓝绿发布和回滚。
- **隔离执行环境**：区分普通云端构建任务与需要专用机器、厂商 SDK、许可证或真实硬件的任务。

## 覆盖范围

平台采用统一的交付管理方式，支持两类项目：

1. **普通应用**：例如 Java、C/C++ 等项目。
2. **嵌入式固件**：例如 Rockchip（瑞芯微/RK）、Qualcomm（高通）、MediaTek（联发科/MTK）等不同芯片平台。

不同项目可以使用不同工具链和执行机器，但构建结果、质量检查、制品追溯、发布和回滚遵循同一套基本规则。

## 交付流程

```text
代码提交
  → 分析本次需要构建的项目
  → 按依赖顺序构建和测试
  → 生成并校验制品
  → 安全检查与归档
  → 发布到目标环境
  → 验证结果；必要时回滚
```

## 从哪里开始

- **第一次学习**：阅读[学习入口](docs/START-HERE.md)，按实际交付流程理解平台。
- **查找专题**：进入[文档导航](docs/README.md)，根据当前工作环节选择文档。
- **查看真实验证范围**：阅读[生产生命周期验收记录](docs/production-verification.md)，区分已验证能力与仍需外部环境验收的能力。

> 文档中的设计目标、仓库代码、自动化测试和真实生产验收是不同层次。具体能力是否已在真实外部系统运行，以对应验收记录为准。
